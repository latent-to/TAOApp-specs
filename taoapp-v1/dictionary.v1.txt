Miners submit containerized inference servers serving Qwen2.5-72B-Instruct via an OpenAI-compatible API. Validators run every submission against a vLLM baseline on the same hardware and score on time-to-first-token (TTFT), throughput, and output correctness. Any language, framework, custom CUDA kernel, or optimization technique is allowed—the only thing that matters is serving the model faster while keeping outputs correct. The long-term vision is for winning servers to become live production endpoints, routing real inference traffic as the fastest and most cost-efficient way to serve high-value open-source models. Pull miner Docker images, start the container on GPU, and run a two-pass evaluation: first a streaming speed pass (TTFT + throughput) without logprobs, then a correctness pass with logprobs enabled. Score = 0.5 x TTFT improvement + 0.5 x throughput improvement vs the vLLM baseline, correctness-gated (first-mismatch logprob check). Miners failing the correctness gate receive score 0.0 regardless of speed. Every model call may include conversation history, tool outputs, files, code, and intermediate state, much of which is repeatedly processed across the same task. This increases inference cost and latency, while limiting how long and effectively agents can operate. SOMA is a Bittensor subnet focused on context compression for AI agents. SOMA develops compression methods that reduce the amount of context sent to language models while preserving, or improving, agent performance. Instead of optimizing compression against static text benchmarks alone, miners compete on real agent tasks where their solutions are evaluated based on both token efficiency and task quality. Miners build compression algorithms and models. SOMA's validation infrastructure runs them against agent workloads, compares their performance with uncompressed baselines, and rewards the strongest solutions. Validators evaluate miner submissions against standardized agent workloads and competition-specific benchmarks. Each solution is tested against an uncompressed baseline and scored based on factors such as agent task performance, weighted token consumption, compression efficiency, and reliability across repeated runs. Evaluation results are aggregated into competition rankings, which are used to determine subnet incentives. Miners design and implement context compression algorithms that reduce agent token usage without degrading task performance. To participate, miners register a hotkey on netuid 114 and submit their solution for the active competition round. Submissions pass through screening and qualification before advancing to full evaluation. Qualified solutions are tested across multiple agent tasks and repeated runs to measure both quality and token efficiency.
